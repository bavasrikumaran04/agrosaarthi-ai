Package / runtime
- name `@google/genai`, version `2.30.0`, ESM package (`"type":"module"`) with CJS build too (`dist/node/index.cjs`); node entry `dist/node/index.mjs`; types `dist/node/node.d.ts` (node condition) / `dist/genai.d.ts`.
- README prerequisite: Node.js 20 or later. README warning: from SDK 3.0.0 Node 22+ is required, Automatic Function Calling will no longer be invokable from `Models.generateContent` (only via Chats), `GenerationConfigThinkingConfig` removed (use `ThinkingConfig`), `LiveConnectConfig.generation_config` removed. README says: "To avoid unexpected updates, pin the SDK version to `< 3.0.0`."
- README quickstart uses the alias model string `gemini-flash-latest`.

Client construction
- `new GoogleGenAI({ apiKey })`. `GoogleGenAIOptions` fields: `enterprise?`, `vertexai?` (alias, `enterprise` is recommended; conflicting values throw), `project?`, `location?`, `apiKey?`, `apiVersion?`, `googleAuthOptions?`, `httpOptions?`.
- Gemini Developer API is the default backend (not Vertex). Default base URL `https://generativelanguage.googleapis.com/`, default API version `v1beta` (Vertex default `v1beta1`). README: "By default, the SDK uses the beta API endpoints ... The stable API endpoints can be selected by setting the API version to `v1`".
- API key is sent as header `x-goog-api-key`. If `apiKey` is missing on the Gemini API, SDK only does `console.warn('API key should be set when using the Gemini API.')` (no throw).
- In Node, if `apiKey` is not passed the SDK reads env `GOOGLE_API_KEY`, else `GEMINI_API_KEY` (if both set it warns and uses `GOOGLE_API_KEY`). Env `GOOGLE_GENAI_USE_ENTERPRISE` / `GOOGLE_GENAI_USE_VERTEXAI` select Vertex. Recommendation: always pass `apiKey` explicitly from app config, and unset `GOOGLE_API_KEY` in the server environment to avoid surprise precedence.
- README: "Avoid exposing API keys in client-side code. Use server-side implementations."

Timeouts, abort, retries (runtime code `dist/node/index.mjs`, class ApiClient.apiCall / createAttemptSignal)
- `HttpOptions.timeout` (milliseconds) exists in `HttpOptions` and can be set on the client (`new GoogleGenAI({apiKey, httpOptions:{timeout}})`) or per request (`config.httpOptions.timeout`). Implementation: a fresh `AbortController` per attempt with `setTimeout(() => controller.abort(), timeout)` (unref'd), so the timeout is PER ATTEMPT; it also adds header `X-Server-Timeout: ceil(timeout/1000)` (seconds).
- `config.abortSignal?: AbortSignal` exists on `GenerateContentConfig` and `EmbedContentConfig`. Doc comment: "AbortSignal is a client-only operation. Using it to cancel an operation will not cancel the request in the service. You will still be charged usage for any applicable operations."
- Timeout and caller abort both call `controller.abort()` with no reason, so `fetch` rejects with a DOM `AbortError` in both cases; the SDK does not throw a distinct timeout class. To tell them apart, pass your own `AbortSignal.timeout(ms)` as `config.abortSignal` and inspect `signal.aborted`/`signal.reason` yourself.
- NO retries by default: retries happen only if `httpOptions.retryOptions` is provided. `HttpRetryOptions`: `attempts` (incl. the initial call; default 5 when retryOptions object given without it; 0 or 1 = no retries), `initialDelay` (seconds, default 1.0), `maxDelay` (seconds, default 60.0), `expBase` (default 2.0), `jitter` (default 1.0), `httpStatusCodes` (default `[408, 429, 500, 502, 503, 504]`). After retries are exhausted the typed `ApiError` is thrown, so `.status` still works.
- `automaticContinuation` (GenerateContentConfig, default true): if a response ends with `finishReason: 'CONTINUATION'` the SDK re-sends the request with `continuationToken` until done; "Timeouts, retries and billing apply to each request". Set `automaticContinuation: false` for a strict latency/cost bound.

Errors
- `class ApiError extends Error { status: number }`; runtime sets `name = 'ApiError'`; exported from `@google/genai`. It is thrown for any HTTP 4xx/5xx. `message` is `JSON.stringify(errorBody)` where errorBody is the parsed JSON error response (Google error envelope `{"error":{"code":<int>,"message":"...","status":"<GRPC_STATUS>", ...}}`) or `{"error":{"message":<text>,"code":<http status>,"status":<statusText>}}` for non-JSON bodies. So to read the gRPC-style status string (e.g. `RESOURCE_EXHAUSTED`) JSON.parse the message. For stream errors the message is `got status: <status>. <json>`.
- Use `err instanceof ApiError` then `err.status`. Network failures throw standard fetch errors (`TypeError: fetch failed`), aborts throw `AbortError`.

### F. generateContent vs Interactions API (https://ai.google.dev/gemini-api/docs/interactions and https://ai.google.dev/gemini-api/docs/interactions/structured-output)
- Interactions API page says it "is currently in Beta. Features and schemas are subject to breaking changes", is "the new standard for building with Gemini, recommended for all new projects", and that "new models beyond the core mainline family ... will launch exclusively on the Interactions API". BUT the same page says: "For production workloads, you should continue to use the standard `generateContent` API. It remains the recommended path for stable deployments, and we will continue to actively develop and maintain it." and the structured-output page says "For stable production deployments, we recommend you continue to use the `generateContent` API." Features not yet in Interactions: Batch API, explicit caching, video metadata, Python AFC.
- Consequence: all current Google doc code samples (structured output, thinking, safety, TTS) are shown in Interactions-API form (`ai.interactions.create`, `response_format`, `generation_config`), so doc snippets must NOT be copy-pasted for `generateContent`. Use the installed SDK's `ai.models.generateContent` types (section 3.1) for production.
- SDK CHANGELOG (https://github.com/googleapis/js-genai/blob/main/CHANGELOG.md, raw fetched): `2.0.0` (2026-05-07) "BREAKING CHANGES - Interactions Only ... The breaking changes are only in interactions. `GenerateContent` usage in unaffected." (steps array replaces outputs; legacy `response_format` deprecated in favour of a polymorphic field; SSE events renamed `interaction.created` / `interaction.completed`). Same release fixed "timeout not functioning". So 1.x -> 2.x is a NO-OP for `ai.models.generateContent`/`embedContent` callers. Other relevant entries: 1.50.0 "Add support for new audio MIME types: opus, alaw, and mulaw"; 1.51.0 "introduce enterprise flag and GOOGLE_GENAI_USE_ENTERPRISE env var" (the `vertexai` flag still works but is documented as superseded); 2.29.0 "Raise default HTTP timeouts so long-running requests aren't killed client-side", "automatically consume the continuation token", "add billable token counts fields"; 2.30.0 (2026-10-14) latest at time of writing: fixes to automatic continuation, adds `gemini-4-argon` to the Interactions Model enum. ### G. Thinking / latency (https://ai.google.dev/gemini-api/docs/thinking, https://ai.google.dev/gemini-api/docs/troubleshooting)
- Table "Controlling thinking": `gemini-3.5-flash-lite` default thinking "On (minimal)", levels minimal/low/medium/high; `gemini-3.8-flash` default On (medium), levels low/medium/high (`minimal` returns an error per model page); `gemini-3.6-flash` default medium, levels minimal/low/medium/high; `gemini-2.5-flash-lite` default Off.
- `max_output_tokens` "sets the maximum number of tokens a response can generate, including thought tokens ... If the model hits this limit while reasoning, it stops generating ... and returns truncated or empty output (while still billing for any thinking tokens generated). To reduce cost or latency without truncating responses, lower `thinking_level` instead of setting a small `max_output_tokens`." (page is Interactions-flavoured; the generateContent equivalents are `maxOutputTokens` and `thinkingConfig.thinkingLevel`, see SDK d.ts and Google's own SDK codegen guide https://raw.githubusercontent.com/googleapis/js-genai/refs/heads/main/codegen_instructions.md which shows `config.thinkingConfig.thinkingLevel: 'LOW'` for Gemini 3 and `thinkingBudget` for 2.5.)
- Pricing: with thinking on, output price applies to output tokens + thinking tokens.
- Troubleshooting page: "Higher latency or token usage often occurs because Gemini 3.x models have thinking enabled by default ... lower the thinking level or turn off thinking." It also says: "we strongly recommend keeping [temperature, top_p, top_k] at their default values for Gemini 3.x models. Changing these parameters (for example, setting the temperature below 1.0) can cause unexpected behavior, such as looping or degraded performance". The same page lists parameter ranges: candidate count 1-8, temperature 0.0-1.0 (as printed), topP 0.0-1.0.
- Structured-output pitfalls (troubleshooting page): "Repeated text in using structured output ... Don't specify the order of fields in your prompt. Make all output fields required."; "Repeated newlines in structured output: ... `\u` escape sequences in your JSON examples can cause the model to use them in its output too ... add a system instruction: In quoted strings, the only allowed escape sequences are \\, \n, and \". Instead of \u escapes, use UTF-8." (relevant to Tamil script output).

### H. Structured output rules (https://ai.google.dev/gemini-api/docs/structured-output)
- Supported JSON-Schema `type`s: string, number, integer, boolean, object, array, null (nullable via `type: ["string","null"]`); `enum` (strings/numbers), `format` (date-time, date, time), `minimum`, `maximum`, `items`, `prefixItems`, `minItems`, `maxItems`, `properties`, `required`, `additionalProperties`, `title`, `description`.
- NOT enforced (silently stripped by server, validate client-side): `minLength`, `maxLength`, `minProperties`, `maxProperties`, `uniqueItems`, `contains`, `minContains`, `maxContains`. `minItems`/`maxItems` ARE enforced. (Zod `.min()` on strings becomes `minLength` -> not enforced.)
- Very large/deeply nested schemas may be rejected with `400 INVALID_ARGUMENT` ("too many states or too much branching"); causes: large `maxItems`, long property/enum names, many enum values, long runs of optional properties, `anyOf` with many alternatives. Output is syntactically valid JSON but "always validate values in your application".
- "Structured outputs with tools" is a Gemini 3-series preview feature.
- Google's SDK guide says use `config: { responseMimeType: 'application/json', responseJsonSchema: {...} }` then `JSON.parse(response.text)` (https://raw.githubusercontent.com/googleapis/js-genai/refs/heads/main/codegen_instructions.md). NOTE that file is partly stale: it still lists `gemini-3-flash-preview` / `gemini-2.5-flash-lite` as default models - the models page is authoritative.

### I. Audio input, transcription and TTS (verified facts only)
- Audio understanding (https://ai.google.dev/gemini-api/docs/audio): audio goes inline when "under 20MB total request size" ("Maximum request size is 20 MB total (including prompts and all files)") else via Files API ("Use the Files API for files larger than 20 MB"). Supported MIME types: `audio/wav`, `audio/mp3`, `audio/aiff`, `audio/aac`, `audio/ogg`, `audio/flac`, `audio/mpeg`, `audio/m4a`, `audio/l16`, `audio/opus`, `audio/alaw`, `audio/mulaw`, `audio/webm`. Technical details: 32 tokens per second of audio (1 min = 1,920 tokens); max 9.5 hours of audio per prompt; downsampled to 16 Kbps; multi-channel combined to a single channel. The page itself points to Google Cloud Speech-to-Text for "dedicated speech to text models with support for real-time transcription" (page predates 3.5 Transcribe).
- Dedicated STT model `gemini-3.5-transcribe` (stable, Aug 2026; https://ai.google.dev/gemini-api/docs/models/gemini-3.5-transcribe and https://ai.google.dev/gemini-api/docs/transcribe): audio file up to 1 hour per request (30 min if diarization or word timestamps), same 13 MIME types as above, auto language detection over "85+ languages" with code-switching, optional `language_codes` BCP-47 hints, custom vocabulary up to 1,000 terms (best <= 100; incompatible with diarization/timestamps), diarization up to 8 speakers, no caching/function calling/thinking/Batch/Flex/Priority; price about $0.005/min. Live variant `gemini-3.5-transcribe-live` limited to 10 minutes per session. TAMIL IS NOT LISTED in the documented supported-language table (the table lists Telugu `te-IN`, Kannada `kn-IN`, Malayalam `ml-IN`, Hindi `hi-IN`, Marathi, Gujarati, Bengali, Punjabi, Odia, Assamese, Nepali, Sindhi, en-IN etc., but no `ta-IN`). Config for it is documented only in Interactions form: `generation_config.transcription_config.{language_codes, custom_vocabulary, mode}`.
- TTS (https://ai.google.dev/gemini-api/docs/speech-generation, https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash-lite-tts): model codes `gemini-3.8-flash-tts` (130 languages) and `gemini-3.8-flash-lite-tts` (101 languages; "fast, cost-efficient ... conversational voice agent cascades"); TAMIL IS LISTED as supported by BOTH (language table row "Tamil | check | check"); language is auto-detected from the input text. Input text only, output audio only; input token limit 8,192; output token limit 16,384 (Gemini API serving limit). 30 prebuilt voices (Zephyr, Puck, Charon, Kore, Fenrir, Leda, Orus, Aoede, Callirrhoe, Autonoe, Enceladus, Iapetus, Umbriel, Algieba, Despina, Erinome, Algenib, Rasalgethi, Laomedeia, Achernar, Alnilam, Schedar, Gacrux, Pulcherrima, Achird, Zubenelgenubi, Vindemiatrix, Sadachbia, Sadaltager, Sulafat). Output audio: unary requests return WAV (`audio/wav`, 24 kHz, mono, 16-bit signed little-endian PCM, 44-byte RIFF header); streaming returns headerless raw L16 PCM (24 kHz mono); alternative encodings documented: `audio/l16`, `audio/mulaw` (8-bit G.711 mu-law), `audio/alaw` (8-bit G.711 A-law) with optional `sample_rate` (e.g. 24000, 16000, 8000) - documented in the Interactions API (`response_format: {type:'audio', mime_type, sample_rate}`; the installed SDK types `AudioResponseFormat.mime_type` = "audio/mp3" | "audio/ogg_opus" | "audio/l16" | "audio/wav" | "audio/alaw" | "audio/mulaw"). For `generateContent` the model page mentions enum values `AUDIO_L16`/`AUDIO_MULAW`/`AUDIO_ALAW` but the installed d.ts exposes no typed field for them => how to request mu-law via generateContent is UNVERIFIED; safest = request default WAV/L16 and transcode (ffmpeg) to 8 kHz mu-law for telephony. Needs `@google/genai >= 2.24.0` for 3.8 TTS (installed 2.30.0 OK). Limits: multi-speaker max 2 speakers; custom voices max 200 per project. Price: see section B.
- Legacy preview TTS models (`gemini-3.1-flash-tts-preview`, `gemini-2.5-flash-preview-tts`, `gemini-2.5-pro-preview-tts`) are shut down no earlier than 2026-11-17 - do not use.

### K. Errors, safety (https://ai.google.dev/gemini-api/docs/api-errors, safety-settings, troubleshooting, rate-limits)
- HTTP status codes documented: 400 (invalid request / failed_precondition e.g. billing disabled), 401 (bad/missing key), 402 (Prepay credits depleted - do not retry), 403, 404 (model not found), 409, 416, 429 (rate limit / daily quota / spend-based limit; body status `RESOURCE_EXHAUSTED`), 499 (client cancelled), 500, 501, 503 (`UNAVAILABLE`, overloaded), 504 (deadline exceeded). Recommended: retry only transient (408, 429, 5xx) with exponential backoff (~1 s, 2 s, 4 s, 8 s) plus jitter and a max retry count; never retry 400/401/402/403. NOTE: the api-errors page documents the Interactions API (snake_case string codes such as `rate_limit_exceeded`, `quota_exceeded`, `model_not_found`, `payment_required`); generateContent returns Google-style bodies `{"error":{"code":<http>,"message":...,"status":"RESOURCE_EXHAUSTED"|...}}` (status strings seen in docs: `RESOURCE_EXHAUSTED`, `UNAVAILABLE`, `INVALID_ARGUMENT`); the SDK puts that whole body JSON in `ApiError.message`.
- Safety settings page: adjustable categories `harassment`, `hate_speech`, `sexually_explicit`, `dangerous_content`, `jailbreak`; default threshold "Off" for Gemini 2.5 and later models; thresholds `off`, `block_only_high`, `block_medium_and_above`, `block_low_and_above`; core child-safety protections always on. In the Interactions API a blocked input/response is an HTTP 400 error with `code: safety`; for generateContent (SDK types) a blocked prompt yields `promptFeedback.blockReason` with no candidates and a blocked response yields `candidates[0].finishReason = SAFETY` (and RECITATION, PROHIBITED_CONTENT, BLOCKLIST, SPII, LANGUAGE, OTHER). Troubleshooting: `BlockedReason.OTHER` = may violate ToS or be unsupported; RECITATION fix = make prompt/context more unique.
